## 历史记录与编写约定

2026 年 2 月的六份设计/实施文档记录了目录迁移前的方案。保留它们用于理解领域规则、设计理由和验收场景；其中的根目录游戏路径、CDN 方案和测试命令不再代表当前实现。查阅时结合 [当前架构](../project-functional-architecture.md) 与 [开发命令](../../README.md)。

仅当任务包含需要追踪的多个阶段或关键决策时新增计划。简单修复无需单独计划文件，也无需读取全部历史文档。

新计划记录以下信息即可：

- **状态与日期**：草案、实施中、完成或已被取代；状态随实际结果更新。
- **目标与范围**：用户可观察到的结果、涉及模块和明确不包含的工作。
- **关键决策与约束**：需要保留的兼容性、数据和发布边界，以及采用方案的原因。
- **阶段与依赖**：有助于协调的工作划分，避免逐条规定工具调用或固定提交步骤。
- **验收与验证**：可观察行为、相关测试/浏览器场景，以及完成条件。
- **结果或未决问题**：实施后记录实际偏差、验证证据和后续事项。

保留有价值的规则测试与边界用例；不要要求所有修改都先制造失败、全量测试或使用某个个人技能。验证通过后，只因新修改、失败或未解决的问题追加检查。

约束维护参考：[OpenAI 模型指南](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-6-astra)和[技能与提示词实践](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra#better-skills)。项目规范保持模型通用，只记录本项目必要的信息与完成边界。
