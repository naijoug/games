# 中国象棋小游戏设计文档

**日期：** 2026-02-26

## 目标
在 `xiangqi/` 目录新增一个中国象棋小游戏，支持：
- 双人对弈（本地同屏）
- 人机对弈（简单/中等/困难三档）
- 先后手选择（人机模式）
- 悔棋、重新开始
- 完整走子规则与终局判定
- 竞赛近似版重复局面判罚（长将/长捉常见形态 + 模糊局面保守和棋）

## 架构
采用与仓库现有小游戏一致的静态前端结构，拆分为规则引擎、AI 引擎和 UI 层：
- `game-core.js`：纯规则引擎（可 Node 测试）
- `ai.js`：人机搜索逻辑（依赖规则引擎）
- `app.js`：浏览器交互与渲染
- `index.html` / `styles.css`：页面结构与样式

## 核心状态模型
规则引擎返回不可变状态对象，至少包含：
- `board`：10x9 棋盘（棋子对象或 `null`）
- `sideToMove`：`red` / `black`
- `status`：`playing` / `check` / `checkmate` / `stalemate` / `draw` / `forbidden-repeat-loss`
- `winner`：`red` / `black` / `null`
- `reason`：终局原因/提示文案 key
- `history`：走子历史（含重复局面分析元信息）
- `moveNumber`：当前手数

单步历史记录包含：
- `from` / `to`
- `pieceId` / `pieceType`
- `capturedPieceId`（如有）
- `positionKeyAfter`
- `givesCheck`
- `chaseTargets`（近似长捉识别使用）

## 规则实现范围（完整走子）
- 将/帅：九宫内直走一格，允许照面吃将（满足路径无子）
- 士：九宫内斜走一格
- 象：斜走两格，不得过河，塞象眼判禁着
- 马：日字走，蹩马腿判禁着
- 车：直线走，路径不可越子
- 炮：走子不越子；吃子需隔一子（炮架）
- 兵/卒：不过河仅前进；过河后可平移；不可后退
- 将帅照面：任何使双方将帅直接照面的局面为非法（需被合法着过滤）

## 终局与状态判定
每步完成后判定对方局面：
- 有合法着且未被将军：`playing`
- 有合法着且被将军：`check`
- 无合法着且被将军：`checkmate`（当前落子方获胜）
- 无合法着且未被将军：`stalemate`（困毙，当前落子方获胜）

## 重复局面判罚（竞赛近似版）
### 基础重复识别
- 使用 `positionKey = 棋子布局 + sideToMove`
- 同一 `positionKey` 重复出现时触发循环分析

### 长将（优先级最高）
- 若某方在循环中的对应着法持续造成将军（`givesCheck = true`），视为长将候选
- 若继续该重复序列应被禁止，则判该方 `forbidden-repeat-loss`

### 长捉（近似实现）
- 基于稳定棋子 ID 跟踪追逐目标
- 覆盖常见反复追逐（车/炮/马）场景
- 使用 `chaseTargets` 对循环内模式做一致性识别

### 模糊/冲突场景
- 判定优先级：长将禁着 > 长捉禁着 > 普通重复和棋
- 双方互相形成禁着候选且难以归责时：`draw`
- 无法稳定识别的复杂循环：`draw`

## AI 设计（三档）
统一接口：`chooseMove(game, { level, timeBudgetMs })`

### 简单
- 浅层搜索（1-2 ply）
- 启发式评分：子力值 + 基础将军奖励
- 轻微随机扰动

### 中等
- Alpha-Beta 搜索（2-3 ply）
- 增强评分：子力、机动性、过河兵、将帅安全（轻量）
- 吃子/将军优先排序

### 困难
- 迭代加深 + Alpha-Beta
- 时间预算控制（返回已完成深度最佳着）
- 更强排序（历史最佳、吃大子优先等）

## UI 交互设计
### 控件
- 模式：双人 / 人机
- 难度：简单 / 中等 / 困难（人机模式可用）
- 执子：我方执红 / 我方执黑（人机模式）
- 按钮：悔棋 / 重新开始

### 棋盘交互
- 点击己方棋子选中
- 高亮合法着点位
- 点击目标格走子
- 轮到 AI 时锁定棋盘输入，显示“AI 思考中…”
- 移动端优先点击交互，不做拖拽

### 悔棋行为
- 双人模式：回退 1 步
- 人机模式：默认回退 2 步（玩家 + AI）；若 AI 尚未走子则回退 1 步
