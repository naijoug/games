# 机器人送快递实施计划

- 状态：完成；日期：2026-09-30。
- 目标：6–10 岁儿童排列动作、运行程序并根据结果修改，让机器人到达收件点。
- 路径：`games/robot/`；遵循[共同约定](README.md)。

## 首版范围与决定

18 个 4×4 至 6×6 固定关卡：6 关直行和转向，6 关绕障碍，6 关单层重复。动作只有前进一格、左转 90°、右转 90°；重复次数为 2–4，循环体只含普通动作，不支持嵌套、变量、条件或文本代码。

题目记录地图、初始朝向、目标和参考程序。程序最多 20 个编辑节点（循环头和循环体指令都计入），展开后最多 64 个动作；运行前同时校验两种上限、重复次数和动作枚举。用结构化指令解释器，不使用 `eval`。

核心接口 `validateProgram`、`compileProgram`、`createRun`、`stepRun`、`resetRun`。编译时保留展开动作到编辑节点的映射；每一步只执行一个动作。撞墙或越界停在当前格并进入“需要修改”，不是游戏结束；朝向正确地随转向更新。

仅在程序全部执行后检查是否到达目标，途经目标后离开不算完成。运行与单步使用相同状态转换。编辑或停止时重置机器人到起点并取消旧运行回调，保留程序。提示先描述执行到哪里出错；第二层可展示参考程序前缀，标明这是参考方案而非对当前程序的最小修复。

## 验收与验证

运行 `node --test games/robot/tests/*.test.js`。

- 覆盖四个初始朝向、左／右转、撞墙停留、重复展开、嵌套拒绝、空循环拒绝、编辑节点及展开长度超限。
- 运行与逐次单步最终状态相同；空程序不误完成；途中经过目标但结束不在目标时不胜利；所有参考程序正确到达。
- 浏览器可只用键盘创建带重复的程序；暂停间隔重开、切关、修改程序后旧回调不能移动机器人；高亮能追溯到循环体内的编辑节点。
